Kitbag · #657 · tool delivery design

Downloadable first-party tools: the experience

Every state drawn on the SM-M156B viewport, 411.4 × 891.4 dp with a 30.5 dp status bar and a 48 dp 3-button nav bar, font scale 1.0. Stage (dark) on the left, Daylight (light) on the right. A fit check at 360 × 800 is at the end.

Colours, type, radii and spacing are copied from packages/core-design/src (tokens.ts, theme.ts, roles.ts, settingsRoles.ts, snackbarRoles.ts) and its components (ListRow, ToolTile, EditRow, Button, Badge, Card, Sheet, Snackbar, LinearProgress); Home and Settings, Tools follow packages/app-shell/src/home and src/settings/ToolsScreen.tsx as built. Icons are the MaterialCommunityIcons glyphs named in icons.ts, inlined as SVG. Versions, sizes and counts are illustrative; the app is 0.31 here, 0.32 in section 8.

Rules: Metronome is the only built-in tool. Tuner, Songs, Stem songs, Play along and Practice history become downloads; their native parts stay in the app. Tools are rebuilt for every app release, attached to the same GitHub release; an installed tool keeps working across app updates unless an update changes the host API major version, the Hermes bytecode version, or the React Native, React, Reanimated or worklets versions. Each APK embeds its release’s signed tool list, so browsing tools needs no network; the update check runs only when Settings, Tools opens with downloads on; the F-Droid build compiles every tool in and has no download code or opt-in screen.

Scenarios: section 0 is a fresh install. Sections 1 to 8 follow a user who installed Tuner, Songs, Stem songs, Play along, Practice history (hidden from Home) and Drone, with downloads on; Practice recorder, Intonation trainer, Click trainers and Spoken count can still be downloaded. Section 9 is an existing user upgrading to the release where today’s tools leave the app.

0. Fresh install

A new install has one tool, the Metronome. Everything else, including today’s Tuner, Songs, Stem songs, Play along and Practice history, is found through More tools. The app opens on Home and asks nothing at launch.

1. Discovery, for a user with tools installed

This user installed Tuner, Songs, Stem songs, Play along, Practice history and Drone, and turned downloads on. Home looks as it does today.

2. One-time opt-in (GitHub build)

The GitHub build asks once, before the first download of executable code. It opens the first time the user taps Install, or Tool downloads in Settings. The F-Droid build has every tool compiled in, no download code and no opt-in screen (7f, 7g).

3. Tool page before install

What it does, sizes, permissions, source and signature, the Kitbag release it came with, and Install. The Install button sits in a bar at the bottom.

4. Install: progress, success, failure

Each step says what is happening. Every failure says that nothing was installed and offers a way forward.

5. Checking for updates

With downloads on, the check runs each time Settings, Tools opens, and only then: no background check and no notification. With downloads never turned on or off, there is no check. Tools ride Kitbag’s releases, so a tool update always comes with a Kitbag update.

6. Remove a tool

Removing keeps the tool’s data by default, so installing it again brings it back. Deleting the data is a separate, explicit choice with sizes shown.

7. Offline, downloads off, and the F-Droid build

Offline and with downloads off, installed tools keep working. Discovery says how to get more without prompting.

8. When a Kitbag update needs tools updated

Most Kitbag updates leave installed tools working. This happens only when an update changes the host API major version, the Hermes bytecode version, or the React Native, React, Reanimated or worklets versions; every downloaded tool then needs its matching build before it runs again. With today’s tools downloaded, that is most of Home. Data is kept meanwhile, and nothing downloads until the user taps. By this point the user has also installed Practice recorder (4c), so seven downloaded tools are affected.

9. Upgrading to the release where tools leave the app

For an existing user of the GitHub build whose Tuner, Songs, Stem songs, Play along and Practice history were part of the app until this update. Their native parts stay in the app; their screens become separate tools. Data is untouched. Path A, the bridge release, is the primary path. Path B is the fallback.

Fit check, 360 × 800

The densest screens at the secondary size, dark only. The opt-in screen and the tool page scroll above their fixed button bar.
